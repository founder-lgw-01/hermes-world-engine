# Composition rules, accepted elements to a reviewed final piece

Paths are workspace-relative. The stage is `05_compose/CONTEXT.md`; common
handoff/revision rules live in `_reference/studio-rules.md`. Templates:
`_templates/composition-brief.md`, `_templates/composition-spec.md`, and
`_templates/composition-record.md`.

## Planning versus execution

The intake stage may write the early composition brief to capture audience-facing
finishing requirements: narration pacing, requested sound/music, exact on-screen
text, safe areas and final delivery. Audience/purpose remain in intake, linked
rather than restated as different facts. Early requirements inform shots but
are not baked into generated animation.

Execution of voice, sound, titles/captions and assembly happens after animation
elements are built and accepted. No composition adapter or new audio integration
is implemented here. Naming ElevenLabs, Remotion or another tool is a proposal,
not an installation or a capability claim. Do not discover, install or test an
adapter on implied permission. Execution needs a separately authorized route,
its readiness evidence and any spending/access approval that scope requires.

## Required input gate

Require an approved intake selecting finishing and the approved composition
brief. Freeze each clip file/hash, accepted record, approved source spec and
filing evidence. A narrative additionally requires an approved, accepted
sequence review naming these exact clips and baseline versions. Recheck input
hashes/status at spec derivation and immediately before any authorized execution.

Do not use a different take, trim away a required event, invent a transition or
change pacing beyond approved intent to conceal an unresolved continuity issue.
Return scope/intent changes to the owner and review the revised baseline. A
single accepted clip may skip narrative review, not its own acceptance/filing.

## Spec sections, in order

1. **Source manifest.** Exact input paths, SHA-256 values and authoritative
   acceptance/filing evidence; include sequence-review provenance when selected.
2. **Brief.** Link approved finishing requirements and surface any unresolved
   or delegated choices. No new creative requirement appears only in instructions.
3. **Timeline.** In order: selected clip, source in/out, timeline start/end,
   approved transition and its reason. Calculate timings from actual media;
   never invent durations to make the planned sequence fit.
4. **Finishing layers.** Exact approved narration/text, source of any supplied
   audio, ownership/permission evidence where needed, placement/timing, safe
   areas, levels and caption requirements. Omit unrequested layers. New audio
   is an explicit separately authorized task, not implied by a text draft.
5. **Delivery.** Requested container, dimensions/aspect, frame rate, audio,
   accessibility or other delivery checks. Unresolved requirements block approval.
6. **At risk and acceptance.** Observable checks for story clarity, identity,
   continuity, pacing, legibility and requested audio; use the shared drift
   checklist's sequence/composition section. Record review limitations honestly.
7. **Execution instructions.** Derived only from sections above, with the named
   authorized route and exact allowed work. Mark execution blocked when no
   approved route/readiness evidence exists; an approved spec is not a render.

## Review and local filing

Inspect the actual final export, not merely the intended timeline. Record actual
media properties, file hash, exact source/spec versions, evidence for every
selected criterion and anything not reviewed. Use `_reference/drift-checklist.md`
without creating a competing character/identity checklist. Sparse inspection
must not be described as exhaustive review; audio needs actual listening or
appropriate evidence, not inference from a waveform or filename.

Create the final record only when an actual export exists. Leave status draft
and verdict empty until the human accepts or rejects the named export. After
acceptance, update permitted status/verdict metadata only; do not rewrite old
findings to imply a better result. The record names the single canonical local
final file. Its acceptance is separate from acceptance of source clips.

A rejected assembly gets the next spec/record attempt; unchanged source clips
remain accepted. Changed shot intent goes upstream. Do not fabricate files,
receipts, hashes or outcomes when execution is blocked. There is no automatic
publication, upload, integration purchase or commit after local final acceptance.
